Everything in filmstrip goes through one `Filmstrip` instance. Create it once, keep it for as long as your app or
your DI graph lives, and pass it to whatever needs to probe, plan, export or preview.

## Register everything

With the `filmstrip` artifact, `allBackends()` registers this target's export backend, the player and the built-in
effects.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/Setup.kt" region="setup-all" />

An instance built with an empty block can only probe, and only on Android and Apple. The same probe returns
`FilmstripError.BackendMissing` on the JVM and in a browser. Anything else reports `BackendMissing` too, naming the
artifact to add.

## Android context

filmstrip picks up the application context through App Startup. `filmstrip-core` ships this entry in its manifest
and the build merges it into your app's, next to any other library's initializer.

```xml title="Merged AndroidManifest.xml"
<provider
    android:name="androidx.startup.InitializationProvider"
    android:authorities="${applicationId}.androidx-startup"
    android:exported="false">
    <meta-data
        android:name="dev.jordond.filmstrip.FilmstripInitializer"
        android:value="androidx.startup" />
</provider>
```

If your app turns App Startup off, or a test runs outside it, pass a context yourself.

<Aside>
Any context works. filmstrip keeps its application context for the whole process, so every instance built
afterwards sees it too.
</Aside>

### Remove the initializer

An app that passes the context by hand can drop filmstrip's initializer from the merged manifest. This removes
only filmstrip's entry and leaves every other library's in place.

```xml title="AndroidManifest.xml"
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools">
    <application>
        <provider
            android:name="androidx.startup.InitializationProvider"
            android:authorities="${applicationId}.androidx-startup"
            android:exported="false"
            tools:node="merge">
            <meta-data
                android:name="dev.jordond.filmstrip.FilmstripInitializer"
                tools:node="remove" />
        </provider>
    </application>
</manifest>
```

An app that runs no App Startup initializers at all removes the provider instead.

```xml title="AndroidManifest.xml"
<provider
    android:name="androidx.startup.InitializationProvider"
    android:authorities="${applicationId}.androidx-startup"
    tools:node="remove" />
```

Either way the app still builds, and `Filmstrip(context) { }` is then the only thing that hands filmstrip a
context.

### Without a context

Nothing throws when the context is missing. The operation that needed it fails with a typed error whose message
says so.

```text
filmstrip could not reach an Application Context. Either keep androidx.startup's InitializationProvider in the
merged manifest, or build with Filmstrip(context).
```

Previewing, rendering a frame and exporting always need a context. Probing and planning need one only for a uri or
an in-memory video, and writing a still only for a `content://` uri.
