Everything in filmstrip goes through one `Filmstrip` instance. Create it once, keep it for as long as your app or
your DI graph lives, and pass it to whatever needs to probe, plan, export or preview.

## Create an instance

`Filmstrip()` holds everything the filmstrip artifacts on the classpath provide. With the `filmstrip` bundle that is
this target's export backend, the player and the built-in effects, and adding `filmstrip-effects-filters` adds the
filters.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/Setup.kt" region="setup-all" />

Anything you register in the block sits in front of those, so your own resolvers and factories are asked first.

## Configure ffmpeg

On the JVM, `ffmpeg { }` sets where the ffmpeg backend finds its programs. It can go anywhere in the block.

<Snippet file="jvmMain/kotlin/dev/jordond/filmstrip/docs/guides/Setup.jvm.kt" region="setup-ffmpeg" />

Without it filmstrip reads `FILMSTRIP_FFMPEG` and `FILMSTRIP_FFPROBE`, then searches `PATH`.

## Bundle ffmpeg

By default the JVM backend runs the ffmpeg on the machine. To ship an app that needs nothing installed, add
`filmstrip-transform-ffmpeg-bundled` next to `filmstrip`.

<Code code={bundled} lang="kotlin" title="build.gradle.kts" />

That's the whole setup. `Filmstrip()` runs the ffmpeg and ffprobe the artifact carries. They are
[bytedeco](https://github.com/bytedeco/javacpp-presets/tree/master/ffmpeg)'s build of ffmpeg {versions.bundledFfmpeg}, unpacked into
`~/.javacpp/cache` the first time the instance needs ffmpeg.

filmstrip looks for ffmpeg in this order and takes the first it finds:

1. `ffmpeg { executablePath = ... }`
2. `FILMSTRIP_FFMPEG`
3. The bundled ffmpeg
4. `PATH`, only when the bundled artifact isn't a dependency

On a platform the artifact has no ffmpeg for, every operation reports `FilmstripError.ToolchainMissing` naming the
platform. It never falls back to `PATH`, so an app doesn't quietly run a different ffmpeg on one machine.

### One platform

The artifact depends on ffmpeg for Linux x86_64 and arm64, macOS arm64 and x86_64, and Windows x86_64, about 130 MB
of jars in all. An app packaged for one platform can drop the rest and add its own back.

<Code code={oneOs} lang="kotlin" title="build.gradle.kts" />

The classifiers are `linux-x86_64`, `linux-arm64`, `macosx-arm64`, `macosx-x86_64` and `windows-x86_64`.

### What it encodes

The bundled build is LGPL, so it has no libx264 and no libx265.

| Platform          | H.264        | HEVC         | HDR export |
| ----------------- | ------------ | ------------ | ---------- |
| macOS             | VideoToolbox | VideoToolbox | Yes        |
| Linux and Windows | openh264     | None         | No         |

On Linux and Windows `VideoCodec.Auto` lands on H.264, and a spec that names HEVC or keeps an HDR grade is planned
the way it is on any device without that encoder. openh264 has [limits of its own](/reference/limits/#openh264).

To get libx264 and libx265, add bytedeco's GPL build for your platform. filmstrip runs it ahead of the LGPL one.

<Code code={gpl} lang="kotlin" title="build.gradle.kts" />

### Licence

filmstrip runs ffmpeg as a separate program and links none of it, so filmstrip's own licence doesn't change. Your
app is what distributes the binaries. The bundled build is under the LGPL version 3, and the GPL build under the GPL
version 3. Either way that means shipping the licence text, saying your app uses FFmpeg, and pointing to the source
bytedeco built it from. Read [FFmpeg's licence page](https://ffmpeg.org/legal.html) before you ship.

## Register by hand

`autoRegister(false)` turns discovery off, so the instance holds only what the block registers. `allBackends()` then
registers this target's export backend, the player and the built-in effects.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/Setup.kt" region="setup-explicit" />

An instance built this way with nothing in the block can only probe, and only on Android and Apple. The same probe
returns `FilmstripError.BackendMissing` on the JVM and in a browser. Anything else reports `BackendMissing` too,
naming the artifact to add.

`transformBackend()` registers the export backend and the built-in effects without the player.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/Setup.kt" region="setup-export-only" />

`playerBackend()` alone gives you preview, with no export.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/Setup.kt" region="setup-player" />

## Android context

filmstrip picks up the application context through App Startup. `filmstrip-core` ships this entry in its manifest
and the build merges it into your app's, next to any other library's initializer.

```xml title="Merged AndroidManifest.xml"
<provider
    android:name="androidx.startup.InitializationProvider"
    android:authorities="${applicationId}.androidx-startup"
    android:exported="false">
    <meta-data
        android:name="dev.jordond.filmstrip.FilmstripInitializer"
        android:value="androidx.startup" />
</provider>
```

If your app turns App Startup off, or a test runs outside it, pass a context yourself.

<Snippet
  file="androidMain/kotlin/dev/jordond/filmstrip/docs/guides/Setup.android.kt"
  region="setup-android-context"
/>

<Aside>
Any context works. filmstrip keeps its application context for the whole process, so every instance built
afterwards sees it too.
</Aside>

### Remove the initializer

An app that passes the context by hand can drop filmstrip's initializer from the merged manifest. This removes
only filmstrip's entry and leaves every other library's in place.

```xml title="AndroidManifest.xml"
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools">
    <application>
        <provider
            android:name="androidx.startup.InitializationProvider"
            android:authorities="${applicationId}.androidx-startup"
            android:exported="false"
            tools:node="merge">
            <meta-data
                android:name="dev.jordond.filmstrip.FilmstripInitializer"
                tools:node="remove" />
        </provider>
    </application>
</manifest>
```

An app that runs no App Startup initializers at all removes the provider instead.

```xml title="AndroidManifest.xml"
<provider
    android:name="androidx.startup.InitializationProvider"
    android:authorities="${applicationId}.androidx-startup"
    tools:node="remove" />
```

Either way the app still builds, and `Filmstrip(context)` is then the only thing that hands filmstrip a
context.

### Without a context

Nothing throws when the context is missing. The operation that needed it fails with a typed error whose message
says so.

```text
filmstrip could not reach an Application Context. Either keep androidx.startup's InitializationProvider in the
merged manifest, or build with Filmstrip(context).
```

Previewing, rendering a frame and exporting always need a context. Probing and planning need one only for a uri or
an in-memory video, and writing a still only for a `content://` uri.
