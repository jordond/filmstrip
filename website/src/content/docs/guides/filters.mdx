Filters are looks that stay out of the `filmstrip` bundle. They live in `filmstrip-effects-filters`, so an app that doesn't
use one doesn't carry one. See [Installation](/start/installation/#modules) for the artifact.

## Register them

Call `filters()` on the builder. A filter with no renderer registered is refused by name at plan time.

## VHS

`vhs` makes a frame look like it was played back from a tape. It softens luma, smears chroma along each line, wobbles the
lines, bends the bottom of the frame like a head switch, and adds streaky noise, dropouts and a tracking band. Every
backend draws the same tape, and the pattern follows the frame's composition time, so a seek or a smaller preview shows the
same picture.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/Filters.kt" region="vhs" />

| Setting     | What it does                                                                                 |
| ----------- | -------------------------------------------------------------------------------------------- |
| `intensity` | How strong the look is. `0f` leaves the frame alone and is listed as an inert notice         |
| `tape`      | `TapeSpeed.SP`, `LP` or `EP`, from sharpest to softest. Defaults to `EP`                     |
| `seed`      | Picks the pattern of noise and events. Equal seeds draw the same tape                        |
| `tracking`  | The band of mistracked tape, `events()`, `rolling()` or `Tracking.Off`. Defaults to `events()` |

`events(chance)` runs a band now and then, each one drifting down the frame and fading out over four seconds.
`rolling(period)` runs one band that is always there, rolling from top to bottom every `period`, the look of a tape that
needs tracking. Both take a block that shapes the band.

| Band setting | What it does                                                                                 |
| ------------ | -------------------------------------------------------------------------------------------- |
| `height`     | How tall the band is, a fraction of the frame height from `0.02f` to `0.5f`. Defaults to `0.07f` |
| `shift`      | The largest sideways slide in the band, a fraction of the width up to `0.1f`. Defaults to `0.02f` |
| `snow`       | How far the band mixes toward black and white snow, from `0f` to `1f`. Defaults to `0.6f`    |

`intensity` scales the slide, the noise and the snow, and the chance of an event band by its square.

A `vhs` on the composition covers the whole frame, bars included. One on a clip or a track doesn't grade the bars, and
picture it moves into a bar lands over the fill. It runs under any overlay at its own scope, so a caption next to it stays
clean. A clip overlay under a composition `vhs` is part of the clip's frame by then, and is burned in with it.

An HDR source tone maps to SDR first. `HdrMode.Auto` reports that as an `HdrToneMapped` adjustment naming the effect, and
`HdrMode.KeepHdr` is refused. See [HDR](/guides/hdr/).

<Aside type="note" title="Limits">
- An Apple device that can't compile a Core Image Metal kernel refuses `vhs` by name. That takes an Apple6 GPU on iOS or on
  macOS 12, and a device below that gets an `Incapable` plan.
- The browser refuses a clip whose own frame is longer on a side than the page's `MAX_TEXTURE_SIZE`, since the pass draws on
  that whole frame.
- ffmpeg reads the grain and dropouts from planes handed over a loopback socket, and draws them with `geq`, at the same
  samples, where it cannot. See [Limits](/reference/limits/#filters) for when.
- The ffmpeg backend refuses `vhs` by name on a build with none of the filters it runs on, like `geq` or `gblur`.
- See [Limits](/reference/limits/#filters) for how close each backend lands.
</Aside>

## CRT

`crt` makes a frame look like it is showing on a curved tube. The picture bows out with black past its edge, scanlines and
a phosphor mask run over it, and the corners fall off. The scanlines and the mask are the average over each pixel, so a
smaller preview draws the larger frame's picture at its own size. Nothing reads the clock, so a seek changes nothing.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/Filters.kt" region="crt" />

| Argument    | What it does                                                                         |
| ----------- | ------------------------------------------------------------------------------------ |
| `intensity` | How strong the look is. `0f` leaves the frame alone and is listed as an inert notice |

A `crt` on the composition covers the whole frame, bars included. One on a clip or a track doesn't grade the bars, and the
picture's curve ends in black while a clear bar stays clear. It runs under any overlay at its own scope, so a caption next
to it stays clean. A clip overlay under a composition `crt` is part of the clip's frame by then, and is burned in with it.

An HDR source tone maps to SDR first. `HdrMode.Auto` reports that as an `HdrToneMapped` adjustment naming the effect, and
`HdrMode.KeepHdr` is refused. See [HDR](/guides/hdr/).

<Aside type="note" title="Limits">
- An Apple device that can't compile a Core Image Metal kernel refuses `crt` by name, the same as `vhs`.
- A track of clips that all carry one equal `crt` at the output's size runs the look once after the join on ffmpeg,
  so a long track holds far less memory.
- On ffmpeg the look runs well under real time and holds a lot of memory per clip. See [Limits](/reference/limits/#filters)
  for the numbers, and how close each backend lands.
</Aside>

## LUT

`lut` maps a frame's colours through a colour table from a `.cube` file. Every backend reads the table trilinearly, and
`intensity` mixes the table with one that changes nothing. A table is a function of each pixel's colour alone, so a seek or
a smaller preview draws the same colours.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/Filters.kt" region="lut" />

| Argument    | What it does                                                                                              |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| `table`     | A `CubeLut` from `CubeLut.parse`, which takes the text of the file. Reading the file is yours             |
| `intensity` | How strong the table is. `0f` leaves the frame alone, and so does an identity table. Both are inert notices |

`CubeLut.parse` holds a grid of 2 to 129 points, applies `DOMAIN_MIN` and `DOMAIN_MAX`, and holds an entry past `0` or `1` at
the end it passed, since an SDR code stops there. It throws an `IllegalArgumentException` naming the line for a 1D table, a
size outside that range, a line it can't read, the wrong number of rows, or a file over 137 million characters.

A `lut` on the composition covers the whole frame, bars included. One on a clip or a track doesn't grade the bars, and a
clear bar stays clear. Colour effects at the same scope run before it, and filters at the same scope run in the order you
added them. It runs under any overlay at its own scope, so a caption next to it stays clean.

The table maps SDR codes, so an HDR source tone maps to SDR first. `HdrMode.Auto` reports that as an `HdrToneMapped`
adjustment naming the effect, and `HdrMode.KeepHdr` is refused. See [HDR](/guides/hdr/). A table authored for HDR isn't
supported.

<Aside type="note" title="Limits">
- An Apple device that can't compile a Core Image Metal kernel refuses `lut` by name, the same as `vhs`.
- media3 and the browser fail by name on a table too large for the GL context's `MAX_TEXTURE_SIZE`. See
  [Limits](/reference/limits/#filters).
- See [Limits](/reference/limits/#filters) for how close each backend lands.
</Aside>

## Camcorder

`camcorder` draws a camcorder's on screen display over the frame, like a blinking `REC`, the date and a tape counter. The
text comes from a pixel font filmstrip draws itself, white with a black edge and the record dot in red, so it looks the
same on every backend and needs no font on the device.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/Filters.kt" region="camcorder" />

Each element is one call, and each takes a `corner`. Elements in the same corner stack in the order you add them.

| Element               | What it shows                                                                        | Corner        |
| --------------------- | ------------------------------------------------------------------------------------ | ------------- |
| `rec()`               | A record dot and `REC`, the dot blinking once a second                               | `TopLeft`     |
| `play()`, `pause()`   | A transport icon and its label. `transport(mode)` takes any `TransportMode`          | `TopLeft`     |
| `date(start, style)`  | The date, `MonthDayYear`, `DayMonthYear` or `YearMonthDay`. `start` sets `recordedAt` | `BottomLeft`  |
| `clock(style)`        | The time of day, `TwelveHour` as `AM 10:32:00` or `TwentyFourHour`                   | `BottomLeft`  |
| `counter(start, withFrames)` | A tape counter, `0:00:00`, or `0:00:00:00` with a frame count at the output rate | `TopRight` |
| `battery(level)`      | A battery with a bar for each third of `level`, blinking while low                   | `TopRight`    |
| `tape(speed)`         | The tape speed, `SP`, `LP` or `EP`                                                   | `TopRight`    |
| `label(text)`         | Fixed text from `A` to `Z`, `0` to `9`, space and `: . / - ' +`                      | `BottomRight` |

`recordedAt` is the date and time the date and clock show at the start of the composition, as a `RecordedAt` with no
time zone. A reading that would run past the last second of 9999 holds at `9999-12-31 23:59:59`. `textSize` is the height of a line as a fraction of the frame height, from `0.01f` to `0.2f`, and the margins
are a fraction of the frame too, so a smaller preview shows the export scaled down. A label with a character outside the
font throws an `IllegalArgumentException` naming it. A `camcorder` with no elements leaves the frame alone and is listed
as an inert notice.

The date, clock and counter read the frame's composition time, the same clock `vhs` runs on, so a seek shows the reading
that time had, and a counter on a clip still counts from the start of the composition.

### Burned in or clean

Where you declare it decides whether the tape degrades it. Inside `vhs { camcorder { } }` the display is added ahead of
the `vhs`, so it is recorded on the tape and smears and wobbles with the picture. Declared after a `vhs` at the same scope
it stays clean, like a VCR's own display over the playback. A `vhs` records one `camcorder`, and a second inside the
same block throws an `IllegalArgumentException`.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/Filters.kt" region="camcorder-order" />

It runs over the fill and under any overlay at its own scope. An HDR source tone maps to SDR first. `HdrMode.Auto`
reports that as an `HdrToneMapped` adjustment naming the effect, and `HdrMode.KeepHdr` is refused. See [HDR](/guides/hdr/).

<Aside type="note" title="Limits">
- ffmpeg lays the display from an animated PNG it writes ahead of the export, so it refuses a `camcorder` whose frames
  have no known end by name.
- ffmpeg carries the display in 4:2:0. Luma lands within a code of the other backends, and chroma is filtered over the
  pixels round each sample, so the record dot blends a little with the pixels next to it. See [Limits](/reference/limits/#filters).
- media3 and the browser need OpenGL ES 3.
</Aside>
