## Probe

`probe` reads a source's metadata and decodes no more than its first video frame. An unreadable file comes back as a
`Failure`, so there's nothing to catch.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/ProbeAndFrames.kt" region="probe" />

`MediaInfo` has the `duration`, a `video` and an `audio` track, either of which is null when the source has none, and
`isExportable`, which is false for DRM-protected files. Those can't be exported or previewed, so check it first.

A source with neither a video nor an audio track fails as `SourceUnreadable`. That includes a file the app can open but
the platform's media service isn't allowed to read, such as one under `/data/local/tmp` on some Android devices.

An MP4 or QuickTime file cut short after its header was written, such as a recording stopped part way, also fails as
`SourceUnreadable`, on every platform, and its message says how many bytes are missing. Its header still lists every
sample, so the probe checks where the last one ends against the file's length. A plan of a clip from such a file is
refused before any export starts.

A video file whose header is whole but whose picture data is damaged, such as one overwritten with noise after it was
written, fails as `SourceUnreadable` too. The probe decodes the first key frame of its video track, once per source,
and a frame that doesn't decode refuses the file.

A video codec the platform has no decoder for, such as ProRes in a browser or on Android, fails as
`DecoderRejectedInput` instead, with the codec the platform named. The same file may probe fine on another platform,
so this says nothing about its bytes. Apps that probe when a video is picked can turn it away there, before a preview
or export tries to play it. A browser can report HEVC as supported and still have no decoder to start, for instance
without hardware decoding, and the probe refuses it the same way.

For an MP4 or QuickTime file, `duration` is the length its movie header gives, which counts only what each track's
edit list presents. An AAC track that opens on an encoder delay doesn't run long by that delay, and every platform
reports the same length for the same file. A fragmented MP4 plays for where its last fragment ends, less what its edit
list skips. Any other container gets the length the platform reads.

On a video track, size a target from `displaySize`, which has rotation and pixel aspect applied, rather than `codedSize`.
`bitDepth` is often null, since only HEVC carries it somewhere every backend can read. `hdrTransfer` is null for SDR.

Android and Apple read a container with core alone. The JVM and the browser need their backend artifact. Without it, both
fail with `BackendMissing`, naming the artifact to add. A still needs no backend on any target.

On the JVM a probe that `ffprobe` hasn't finished within its deadline is stopped and refused as `TimedOut`, which names
the read and its deadline, rather than leaving the call hanging. See [Limits](/reference/limits/#probe-deadline).

## Capabilities

`capabilities` asks what this device's encoders can do. The answer is cached per process. On the JVM a test encode
that runs past its deadline fails the call naming the encoder, and that failure isn't cached, so asking again measures
again.

On the JVM, `plan` and `export` don't need this answer. They test-encode only the encoder the plan picks, and only at
the sizes that plan writes, so a small export never waits on an 8K encode or on an encoder it doesn't use. A test
encode the plan does need that runs past its deadline refuses the plan as `TimedOut`.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/ProbeAndFrames.kt" region="capabilities" />

`encoderFor` answers one codec's limits, such as `minSize`, `maxSize`, `maxFrameRate` and `maxBitrate`, or null when
there's no encoder for it. To find out what will happen to one particular edit, use
[`plan`](/guides/export/#plan), which already takes all of this into account.

## One frame

`frame` renders the frame covering an instant of a composition, with its effects applied. You own the image and have to
close it.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/ProbeAndFrames.kt" region="frame" />

Leave `heightPx` null to render at the composition's own output height. A height at or above that height renders at that
height too, since a frame is never scaled up. Zero or less fails with `InvalidComposition`.

For one source with no edit, pass the source directly.

## Many frames

`frames` emits one result per position, each as it's ready. It's made for a timeline strip, so a frame may come from the
nearest sync sample rather than the one covering its position. `presentationTime` says where each one actually landed.
Use `frame` when a position has to be exact.
