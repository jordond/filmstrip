`preview` opens a `VideoPlayer` over the same composition an export takes, and draws it with the same backend, so the
preview shows what the export writes.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/Player.kt" region="open" />

`preview` returns right away and loads in the background. You own the player and have to `close` it. Without
`filmstrip-player` registered, the player reports `PlaybackError.BackendMissing` instead of throwing. A browser reports
the same error, naming `filmstrip-transform-webcodecs`, when `webCodecsBackend()` isn't registered.

A preview writes no file, so a device with no video encoder still previews and only its exports are refused. In a
browser that preview plays its audio too, given a WebCodecs `AudioDecoder`. A browser needs a WebCodecs `VideoDecoder`
to draw, and one without it reports `PlaybackError.UnsupportedFormat`. See
[Limits](/reference/limits/#browsers-without-webcodecs).

`config` sets how hard a preview works. `CapHeight` limits its height without changing what an export writes.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/Player.kt" region="quality" />

## State and events

`state` is a `StateFlow` of consistent snapshots.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/Player.kt" region="state" />

`events` carries the things that happen once, like a seek landing or a loop wrapping. It replays nothing, so subscribe
before you issue commands.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/Player.kt" region="events" />

`positionFlow` follows the playhead, snapped to the tick you ask for. `currentPosition` reads it once. Both report a
seek's target as soon as it's issued, so a scrubber thumb doesn't snap back to where it was.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/Player.kt" region="playhead" />

Each of these has a listener form too, `addStateListener`, `addEventListener` and `addPositionListener`, for callers
without coroutines.

## Transport

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/Player.kt" region="transport" />

- `seekTo` always yields one `SeekCompleted`, naming the frame it landed on. `SeekAccuracy.Nearest` lands on a nearby
  frame, before or after the one asked for, which suits a moving finger. The playhead reads the frame asked for until the
  seek completes, then moves once to the frame it landed on.
- `beginScrub` and `endScrub` wrap a drag. Between them the engine relaxes seek accuracy, and `endScrub` settles on the
  exact frame.
- `setLoopRange` wraps playback at the end of the range and reports `RangeLooped`. A range the composition ends inside wraps
  there and reports no `Ended`. A range that starts at or past the end has nothing to loop, so playback runs to the end. A
  wrap only happens during playback, so a paused seek past the range stays where it lands. After a wrap the playhead
  reads the range's first frame.
- `setPlaybackRange` confines playback without changing the composition, so a trim drag previews without a rebuild.
- `setVolume` sets monitor volume, which only the player hears. To change the export's level, see [Audio](/guides/audio/).
- A failure stops the player and keeps `playWhenReady`. The next load tries again, even with the same composition, and
  plays if a play is still wanted.
- On Apple, `play` after a failure starts nothing and the status stays `PlaybackStatus.Error` until you load again.
  Playback that stops before the end reports `PlaybackEvent.Failed` once per play or seek, with the platform's error.

## Shuttle

A shuttle is picture search: the picture runs at a signed rate, forwards or backwards, with every effect still
applied. It's preview only and never reaches an export.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/Player.kt" region="shuttle" />

- The rate is composition seconds per second, negative for backwards, anything but zero up to 32 either way. Any
  other rate throws `IllegalArgumentException`.
- The player shows as many frames as the device can draw and skips the rest, so the playhead keeps to the rate on a
  slow device. `positionFlow` and `currentPosition` report each frame as it's shown.
- Audio is muted until the shuttle ends.
- `state.shuttleRate` holds the rate, and `playWhenReady` reads false while a shuttle runs.
- `beginShuttle` on a running shuttle changes the rate and carries on from the frame showing.
- `endShuttle` carries on from the frame showing, playing if it was playing before and paused if it wasn't. `play`
  and `pause` end a shuttle into that state. `beginScrub` and `stepFrames` end it too, and `seekTo` moves it.
- A shuttle stays inside the playback range when one is set. A loop range doesn't wrap it.
- At either end the picture holds and `ShuttleReachedEdge` is reported once. The shuttle stays on until you end it.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/Player.kt" region="shuttle-edge" />

## Features

`features` says what this backend can do on this device. Check it before you show a control, so you don't show one
that does nothing.

| Feature               | Android              | Apple | Browser                            | JVM |
| --------------------- | -------------------- | ----- | ---------------------------------- | --- |
| `FrameReadback`       | ✓                    | ✓     | Needs WebGL2                       | ✓   |
| `FrameStepping`       | ✓                    | ✓     | Needs WebGL2                       | ✓   |
| `LiveParameterRedraw` | ✓                    | ✓     | Needs WebGL2                       | ✗   |
| `AudioMonitoring`     | Depends on device    | ✗     | Needs Web Audio and `AudioDecoder` | ✗   |
| `HdrPreview`          | When the display can | ✗     | ✗                                  | ✗   |
| `PlaybackSpeed`       | ✗                    | ✗     | ✗                                  | ✗   |
| `Shuttle`             | ✓                    | ✓     | Needs WebGL2                       | ✗   |

`readback` hands you a rendered preview frame, after effects and before encoding.

## Changing the composition

`setComposition` loads a new value. It's cheap to call often. An equal composition does nothing, a change to effect
parameters redraws in place, and only a structural change rebuilds, like adding a clip or a trim that
changes the duration. Debounce structural edits, so a drag-reorder issues one rebuild and not thirty.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/guides/Player.kt" region="swap" />

A load with no `startAt` holds the playhead. The transport stays where it was, so a playing preview keeps playing and a
paused one stays paused. Where the playhead lands depends on that transport:

- A paused playhead lands on the frame it rounds to.
- A playing playhead lands on the first frame at or after its time.
- A playhead past the end of a shorter composition lands on the last frame.
- A playing playhead at or past a loop range's wrap lands on the start of the range.

`previewInfo` says what's being delivered, including its `outputSize`, its `parity` with the export and its `inertNotices`,
the same ones the export's plan lists.

<Aside type="note" title="Limits">
- On Android a `Nearest` seek is no faster than an exact one.
- The ffmpeg preview waits for a scrub to settle instead of landing on a nearby frame.
- On ffmpeg a changed effect parameter restarts the preview, so it reports no `LiveParameterRedraw`.
- On Android a shuttle lands every frame exactly, so reverse and 4K run at fewer frames a second than on Apple.
- The ffmpeg preview has no shuttle. `beginShuttle` and `endShuttle` do nothing there.
- A preview doesn't encode, so it won't show compression artifacts. Late frames are dropped, so playback can be less
  smooth than the export.
</Aside>
