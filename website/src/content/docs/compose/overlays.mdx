`filmstrip-compose-ui` puts any composable on a `VideoStage`, where a drag moves it, a pinch scales it and a twist
turns it. `filmstrip-compose` bakes what the stage draws into image overlays, so a title card, a sticker or a caption
with a custom font is written once in Compose and drawn into the export.

The baked picture is an ordinary image overlay, so its timing, animation and backend limits are the ones in the
[Overlays guide](/guides/overlays/).

<PagePlayground {...frontmatter.playground} />

For a whole editor built on this page, the [stories sample](/demo/stories/) lays text, stickers and a drawing over a
clip, with snapping, a bin, timing and undo, on touch and with a mouse and keyboard. Its source is in `sample/stories`.

## The element

Any composable works. It's the same one on the stage and in the export.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/compose/ComposedOverlays.kt" region="title" />

## On the stage

An `OverlayTransform` says where the element's centre sits as a fraction of the frame, how much bigger it is drawn and
how far it's turned clockwise in degrees. A `ComposedOverlayState` holds what the stage draws, and the stage records
each element into it. Its `OverlayCanvas` sets how wide the frame is to the content, 360 dp by default, with the height
following the stage's aspect. Content written in dp then lays out the same on a phone, a desktop window and the export.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/compose/ComposedOverlays.kt" region="live" />

`ComposedOverlay` is controlled, so it moves only when the transform you pass back changes. A drag holds the element's
centre on the frame and a pinch holds the scale between `ComposedOverlayDefaults.MIN_SCALE` and `MAX_SCALE`. Only a
touch on the turned element is taken, so several stacked on one stage each get their own. `onSelect` hears which one
was touched, and the sample keeps that index as the selected title. Pass `enabled = false` to show an element without
taking touches.

## Mouse and keyboard

A mouse can't pinch or twist, so a selected element shows two handles. A drag on the one at its bottom corner scales it
about its centre, and a drag on the one above its top edge turns it. The turn handle moves below the element when
above would be off the stage. `handles` says when they show.
`ComposedOverlayHandles.Auto`, the default, shows them once a mouse or a hovering stylus has been over an element of
the stage and hides them again when a finger touches one. `Always` and `Never` do what they say.

Over a selected element the wheel scales it, and turns it with Shift held. The wheel is only taken there, so the page
still scrolls everywhere else.

`Modifier.composedOverlayKeys` gives the keyboard the same steps. It makes its node focusable and never takes focus by
itself, so request focus when an element is selected.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/compose/ComposedOverlays.kt" region="keys" />

| Input | Does | With Shift |
| --- | --- | --- |
| Wheel | Scales by `WHEEL_STEP` a notch, an eighth of a doubling | Turns by `TURN_STEP`, 5 degrees a notch |
| Arrows | Move the centre by `NUDGE`, 0.5% of the frame | `COARSE_NUDGE`, 5% |
| `+` and `-` | Scale by `WHEEL_STEP` | The same |
| `[` and `]` | Turn by `KEY_TURN_STEP`, 1 degree | `COARSE_KEY_TURN_STEP`, 15 degrees |

The figures are constants on `ComposedOverlayDefaults`. Every step goes through the limits a drag and a pinch are held
to. Delete, Escape and undo are left to you, since the element list is yours.

`onGestureChange` reports `true` when a touch or a handle drag takes the element and `false` when it ends, which is
when to open an undo step or show a bin to drop the element on. A wheel notch and a key press are one step each and
don't report.

## Bake it

`Filmstrip.planWithOverlays` plans the export with everything the stage draws. It plans once to read the frame the
export writes, has the state bake each element onto that frame, and plans again with the baked overlays after the
composition's own effects. The verdict it returns is the one to report and run.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/compose/ComposedOverlays.kt" region="export" />

The bake replays what the stage recorded, so the element isn't declared a second time and the file can't lay it out
differently from the screen. Each overlay comes back at `OverlayPosition.At` with exactly the pixels of the frame the
element covers, in the order the stage draws them, and an element with none of itself on the frame is left out. The
baked overlays never enter the preview's composition, so dragging never re-plans the preview.

Unlike `plan`, this draws and encodes pictures, so call it when you export. The stage has to be on screen, and
`bake` throws an `IllegalStateException` when no stage is drawing for the state or it isn't drawn within 10 seconds.

## When it shows

`opacity`, `visibleDuring` and `animation` mean the same on the stage and in the file. A stage with a player follows
its playhead: the element is hidden while the playhead is outside `visibleDuring`, and inside it the element is drawn
at the frame `animation` gives for that time. A hidden element takes no touch, so the touch goes to whatever is under
it.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/compose/ComposedOverlays.kt" region="timed" />

A selected element is held still. It's drawn where you put it at its own `opacity`, wherever the playhead is, so you
can move a title that has already left or one that is midway through its fade. That's `still`, which follows
`selected` unless you pass it. A stage with no player, or a player that hasn't loaded yet, draws every element still.

`shown = false` hides an element for your own reasons, and it wins over `still`. The element is laid out and recorded
either way, so the bake is the same picture wherever the playhead is.

Only `content` is recorded. Whatever you put on `modifier`, like a wash while the element is dragged, stays on the
stage.

## Editing on the stage

A text field laid out as an element breaks its lines where the caption will. Pass `baked = false` so the field and its
cursor never reach the export, and put the finished caption on the stage as an ordinary element.

## From a view model

`ComposedOverlayState` is a plain class with a public constructor, so a view model can own it and the screen passes it
to the stage. Code that exports only needs the `OverlayBaker` it implements.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/compose/ComposedOverlays.kt" region="viewmodel" />

`OverlayBaker` is a single function, so a test passes a lambda and needs no stage.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/compose/ComposedOverlays.kt" region="test" />

A state draws on one stage at a time, and once that stage leaves composition it holds nothing the stage made.

## Content on no stage

A template or a batch export has nothing on screen to record. `OverlayCapturer` bakes a composable you hand it. Mount
one `OverlayCaptureHost` for the capturer somewhere on screen.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/compose/ComposedOverlays.kt" region="host" />

Then capture each element on the frame the export writes, which is the output size of a first plan.

<Snippet file="commonMain/kotlin/dev/jordond/filmstrip/docs/compose/ComposedOverlays.kt" region="capture" />

The capture lays the content out on the canvas, draws it the way the stage does and hands back an `ImageOverlay`, or
null when none of the element lands on the frame. Content that loads a font or an image asynchronously holds `ready`
until it has. Add the overlays to the composition and plan again, since that's the export that runs.

<Aside type="note" title="Limits">
- A stage that isn't on screen is never drawn, so it can't bake. `OverlayCapturer` is for that case.
- Put each `ComposedOverlay` straight in the stage's content. On desktop, iOS and the web a layer of your own between
  the stage and an element hides the draw order from the bake.
- Content that draws into a layer of its own, like a blur or `CompositingStrategy.Offscreen`, is rasterised at its
  layout size before the bake scales it.
- `OverlayCapturer` captures on the frame you pass as `output`. When the export frame differs from it, because the
  encoder aligns the size or `heightPx` caps it, the backend resamples the picture.
- A composed overlay is an 8-bit sRGB picture. On an HDR grade its white lands at the 203 nit reference white like any
  overlay picture.
- A composed overlay's rotation is fixed when it's baked. Its `animation` moves and fades the baked picture.
- An `animation` moves and sizes what the stage draws, not what it touches. Midway through a slide or a scale an
  element still takes a touch on the box you put it at. A selected element is held still, so it has no such gap.
- Colour emoji in a composed overlay need a font that has them, and a browser needs one bundled with the app.
- Apple holds 20 bytes for each pixel of a composed overlay's picture, which is at most one output frame.
- Android 8 and 8.1 capture through a different snapshot path than Android 9 and later, and only Android 16 was
  measured.
- Composed overlays go on the composition's output frame only, since a clip's frame size isn't public.
</Aside>
