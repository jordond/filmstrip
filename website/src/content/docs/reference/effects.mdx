An unsupported effect makes the plan `Incapable` and names the effect. `withoutUnsupported` gives you the same plan
without it. See [Export](/guides/export/#plan).

## Inert effects

An effect that changes nothing is left out of the export and listed on the plan's `inertNotices`. It isn't reported
as an `Adjustment`, and it doesn't stop a stream copy.

- A color effect that changes nothing, like a brightness of one or a whole turn of hue, or several that cancel out.
- A whole turn of `rotate`, or a `crop` to the aspect the frame already has.
- An overlay at zero opacity, with empty text, or with a window outside its scope.

## Where the backends differ

### rotate

Android, Apple and ffmpeg turn a frame by any angle. The browser only turns by multiples of 90 and refuses any other
angle.

### kenBurns

ffmpeg refuses it.

### Color effects

Every backend applies the same color math. On an SDR export, ffmpeg can land one code value below the others when an
effect mixes channels, like `sepia` or `hueRotate`.

### blur and vignette

On Apple both run a Core Image Metal kernel, which needs an Apple6 GPU on iOS or macOS 12. On ffmpeg `blur` runs through
`convolution` with the shared kernel and 8-bit RGB, landing within 2.5 codes of it, and `vignette` rounds through RGB and
back, landing within 1.5 codes.

### imageOverlay

- A browser page can't read a file path, so it refuses `ImageSource.Path`.
- Which picture formats draw depends on the backend. See [Codecs](/reference/codecs/#overlay-pictures).
- Android and the browser refuse a picture longer on a side than the GPU's maximum texture size.

### textOverlay

- Each backend draws with its own fonts and line breaking. A preview and its export always break on the same words,
  but two backends can differ.
- ffmpeg draws with the fonts installed on the machine, and refuses a character none of them can draw.

### Overlay animation

On Android an overlay animated off the frame stops at the edge instead of leaving it.

### Overlays on an HDR grade

On an HDR grade overlays keep the brightness of their colors on every backend. Android on an HLG grade is close but
not exact, and the plan reports it as approximated. See [Limits](/reference/limits/#hdr-text-and-pictures).
