import { MIN_IOS, MIN_MACOS, versions } from '../../../lib/versions'

Each target has one backend. With the `filmstrip` bundle, `allBackends()` registers the right one. If you depend on a
backend directly, call its own function.

| Backend      | Targets           | Artifact                           | Register with           |
| ------------ | ----------------- | ---------------------------------- | ----------------------- |
| Media3       | Android           | `filmstrip-transform-media3`       | `media3Backend()`       |
| AVFoundation | iOS and macOS     | `filmstrip-transform-avfoundation` | `avFoundationBackend()` |
| WebCodecs    | `js` and `wasmJs` | `filmstrip-transform-webcodecs`    | `webCodecsBackend()`    |
| ffmpeg       | `jvm`             | `filmstrip-transform-ffmpeg`       | `ffmpegBackend()`       |

## What each one needs

### Media3

Android API {versions.minSdk} or later. There's nothing to set up, filmstrip picks up the application context through
App Startup. Which codecs and sizes you get depends on the device's encoders.

### AVFoundation

iOS {MIN_IOS} or macOS {MIN_MACOS} or later. Nothing else to install. Which video codecs you get depends on the
device.

### WebCodecs

A browser with WebCodecs and WebGL2. Without a `VideoEncoder` the browser can preview but not export video. Keeping an
HDR grade also needs a float framebuffer and a VP9 Profile 2 encoder. See
[Limits](/reference/limits/#browsers-without-webcodecs).

### ffmpeg

`ffmpeg` and `ffprobe` {versions.ffmpeg} or later, installed on the machine. filmstrip doesn't ship them, see
[Requirements](/start/requirements/#ffmpeg) for how it finds them. Some features depend on how ffmpeg was built:

| To do this                   | The build needs                                       |
| ---------------------------- | ----------------------------------------------------- |
| Encode H.264                 | `libx264` or `h264_videotoolbox`                      |
| Encode HEVC                  | `libx265` or `hevc_videotoolbox`                      |
| Encode VP9                   | `libvpx-vp9`                                          |
| Encode AAC or ALAC           | The `aac` or `alac` encoder                           |
| Tone map                     | The `lut1d`, `geq` and `colorchannelmixer` filters    |
| Draw `Fill.Blur`             | `convolution`, and `colorchannelmixer` to dim it      |
| Draw an AVIF or HEIC picture | A decoder for it                                      |
| Draw a JPEG XL picture       | `libjxl`                                              |

## Preview features

`features` on a player says what this backend can do on this device.

| Feature               | Android              | Apple | Browser                            | JVM |
| --------------------- | -------------------- | ----- | ---------------------------------- | --- |
| `FrameReadback`       | ✓                    | ✓     | Needs WebGL2                       | ✓   |
| `FrameStepping`       | ✓                    | ✓     | Needs WebGL2                       | ✓   |
| `LiveParameterRedraw` | ✓                    | ✓     | Needs WebGL2                       | ✗   |
| `AudioMonitoring`     | Depends on device    | ✗     | Needs Web Audio and `AudioDecoder` | ✗   |
| `HdrPreview`          | When the display can | ✗     | ✗                                  | ✗   |
| `PlaybackSpeed`       | ✗                    | ✗     | ✗                                  | ✗   |

See [Player](/guides/player/#features) for what each one means.

## Preview parity

`previewInfo` reports how closely a preview matches its export, and `parityNotes` has the detail per effect. Every
built-in effect matches exactly, apart from these.

| Effect        | Android       | Apple         | Browser | JVM           |
| ------------- | ------------- | ------------- | ------- | ------------- |
| `TextOverlay` | `Approximate` | `Approximate` | `Exact` | `Approximate` |
| `Scale`       | `Exact`       | `Exact`       | `Exact` | `Approximate` |

`TextOverlay` can differ in how glyph edges are smoothed, but line breaks and size always match. `Scale` on ffmpeg
resamples differently from its preview, so fine detail on a downscale can look slightly different.
