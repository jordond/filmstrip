Each backend checks the device's encoders when it plans. If the codec you asked for isn't there, the export falls back
to another and reports a `CodecFallback`. A `strict` spec refuses instead.

## Video

| `VideoCodec` | Android | Apple | Browser | JVM |
| ------------ | ------- | ----- | ------- | --- |
| `H264`       | ✓       | ✓     | ✓       | ✓   |
| `Hevc`       | ✓       | ✓     | ✓       | ✓   |
| `Vp9`        | ✗       | ✗     | ✓       | ✓   |
| `Vp8`        | ✗       | ✗     | ✗       | ✗   |
| `Av1`        | ✗       | ✗     | ✗       | ✗   |

`Auto` tries H.264 and then HEVC. The browser tries H.264, then VP9, then HEVC. ffmpeg only writes VP9 when you ask for
it, and only if its build has `libvpx-vp9`.

Keeping an HDR grade needs a specific codec, HEVC on Android, Apple and ffmpeg, and VP9 Profile 2 in the browser. See
[HDR](/guides/hdr/#keeping-a-grade).

## Audio

| `AudioCodec` | Android | Apple | Browser                | JVM |
| ------------ | ------- | ----- | ---------------------- | --- |
| `Aac`        | ✓       | ✓     | Depends on the browser | ✓   |
| `Alac`       | ✗       | ✗     | ✗                      | ✓   |
| `Opus`       | ✗       | ✗     | Depends on the browser | ✗   |
| `Mp3`        | ✗       | ✗     | ✗                      | ✗   |
| `Flac`       | ✗       | ✗     | ✗                      | ✗   |
| `Vorbis`     | ✗       | ✗     | ✗                      | ✗   |

`AudioCodec.None` writes no audio track.

If the composition has audio but no encoder writes a codec the container takes, the export is written without audio
and reports an `AudioDropped` adjustment. A `strict` spec refuses instead, and an `AudioOnly` composition is always
refused. A muted composition reports nothing.

Whether a browser encodes AAC and Opus depends on the platform it runs on. `Auto` writes AAC where the container takes
it and Opus otherwise. Opus is encoded at 48 kHz only. WebM can't hold AAC, so a WebM export writes Opus, and asking for
AAC there reports a `CodecFallback`.

## Stream copy

A codec no backend encodes can still end up in an export when the stream is copied without re-encoding.

| Stream | Every backend copies  | The browser also copies |
| ------ | --------------------- | ----------------------- |
| Video  | H.264, HEVC, VP9, AV1 | VP8                     |
| Audio  | AAC, MP3, Opus, FLAC  | Vorbis                  |

What stops a copy is on [Limits](/reference/limits/#stream-copy).

## Containers

Android and Apple write MP4. The browser writes MP4 too, apart from an SDR VP9 export and an audio-only Opus export,
which are WebM. An audio-only MP4 is named `.m4a`. ffmpeg picks the container from the sink's file extension, and uses
MP4 for a temporary sink.

## Overlay pictures

| Format  | Android     | Apple       | Chrome      | JVM (ffmpeg)  |
| ------- | ----------- | ----------- | ----------- | ------------- |
| PNG     | ✓           | ✓           | ✓           | ✓             |
| JPEG    | ✓           | ✓           | ✓           | ✓             |
| WebP    | ✓           | ✓           | ✓           | ✓             |
| GIF     | First frame | First frame | First frame | First frame   |
| HEIC    | From API 28 | ✓           | ✗           | ✓             |
| AVIF    | From API 31 | ✓           | ✓           | ✓             |
| JPEG XL | ✗           | ✓           | ✗           | With `libjxl` |

A picture a backend can't decode is refused by name.

- Android can't decode a 10-bit AVIF on API 33 or a 12-bit HEIC, and decodes a 12-bit AVIF only from API 36.
- Chrome reads an AVIF deeper than 8 bits as 8 bits, and the plan reports it as degraded.
- ffmpeg needs a build that decodes AVIF and HEIC.
- Apple draws whatever the OS version can decode.

<Aside type="note">
Every backend respects EXIF orientation, and the crop stored in an AVIF or HEIC.
</Aside>
