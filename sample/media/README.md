# Sample clips

The clips the sample app offers instead of asking for a file. They exist so a bug report can name
an input anybody else can fetch.

They are served from `https://filmstrip-media.jordond.dev`, an R2 bucket with the CORS rules in
`cors.json`, which is what lets the browser build read them at all.

## What is in here

Most of the corpus is generated by ffmpeg from its own `testsrc2` and `sine` sources. Nothing in
those clips is anybody's work, so there is nothing to licence, and `generate.sh` reproduces them
byte for byte on any machine with the same ffmpeg.

Each one exists for a reason: a container a backend may not read, a rotation that has to survive a
crop, audio that stops before the video does, a frame size past what a phone will encode.

Two clips are real footage, because synthetic frames say nothing about how an encoder handles
grain, motion and shadow:

| Clip | Source | Licence |
|---|---|---|
| `tears-of-steel-720p.mp4` | Tears of Steel, (CC) Blender Foundation, mango.blender.org | CC BY 3.0 |
| `nasa-orion-earth.mp4` | Artemis I, Orion's first imagery of Earth, NASA | Public domain |

Both are excerpts, re-encoded. CC BY asks for attribution, so the clip list carries it on the row
and this table records where it came from.

## Rebuilding

```bash
./generate.sh   # writes build/, needs ffmpeg with libx264, libx265, libvpx-vp9 and libsvtav1
./upload.sh     # publishes build/ to the bucket, needs wrangler logged in
```

`generate.sh` pulls the two real clips over the network and cuts them locally, so a rebuild needs
those sources to still be up.

After changing the corpus, update `SamplePreset.kt` with the new names, byte sizes and durations.
The sample compares the size on disk against the size in the catalogue to decide whether a cached
clip is complete, so a wrong number there means a clip downloads on every run.
